## 亲自重算，不只看最后一行

在仓库根目录运行 `python`，输入：

```python
import json
from pathlib import Path
report = json.loads(Path("results/routing/first/evaluation.json").read_text(encoding="utf-8"))
for label in ("账单", "账户", "物流"):
    group = [r for r in report["candidate"] if r["label"] == label]
    print(label, sum(r["correct"] for r in group), "/", len(group))
for row in report["candidate"]:
    if not row["correct"]:
        print(row["id"], row["message"], row["label"], "->", row["prediction"])
print("改善", report["wins"], "回退", report["regressions"], "非法", report["invalid"])
```

**完成后核对**：默认离线基线 11/12，候选 12/12；有一条由错变对，零条由对变错。每个标签只有四题，单题就能改变该组 25 个百分点。即使 12 条题均无回退，也不能由此断言真实流量没有回退。深入看基线曾错派的混合意图工单 test-04：任务定义是否清楚？是标注分歧、陌生词，还是模型给次要意图更高权重？写出可区分这几种解释的新开发样例。

## 写交接记录

提交给接班同事的记录应含下面六项，可复制到你的实验目录：

1. **任务和范围**：支持的标签、输入语言、尚未覆盖的业务类型。
2. **复现**：Git 提交、Python 版本、两条执行命令、运行名、frozen_digest 和 test_hash。语言模型实验另加服务版本和模型 ID。
3. **证据**：基线与候选的配对成绩、各标签分母、改善/回退 ID、非法输出数量。
4. **失败分析**：引用一个具体错例，区分已观察到的行为和待验证的原因。
5. **决定**：写「暂缓发布」（hold）或「进入影子验证」（shadow），列出触发的门槛。说明两种方法使用了哪些人工标签，哪些假设还没测。
6. **下一班怎么做**：影子阶段记录请求 ID、两条预测、延迟、最终人工裁决；先抽查分歧样本，同时随机抽查两者一致的样本。发生高代价错派或延迟超出业务约定就停用候选旁路，继续使用已冻结的基线。仓库提供离线评估，真实服务部署和回退需要团队环境。

## 独立作业 · 不用默认答案完成迁移

把任务换成你熟悉领域里的三类请求。先在独立分支写标签规范和至少三组容易混淆的例子。改 LABELS、系统提示和四份 JSONL；保持每行 id、message、label 三个字段。默认特征提取器使用汉字及相邻双字，也保留连续的英文字母和数字，更换语言时先检查 tokens 的输出。先定拆分和门槛，再运行开发与最终评估；小数据允许最终决定为「暂缓发布」。

**交付验收**：让另一人按你的任务卡和命令从干净检出复现决定；让对方提供三条未见工单，现场解释预测、失效条件及下一步取证方法。保留任务卡、代码差异、两份报告、评审记录。这几项构成你接手模型评估与反馈迭代任务的第一份工作样本。
